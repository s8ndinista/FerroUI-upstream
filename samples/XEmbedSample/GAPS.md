# XEmbedSample: gaps

What the sample does that the port does differently. The sample has no markup. It runs on Linux with an X server and GTK 3; `cargo check -p xembed-sample --bins --target x86_64-unknown-linux-gnu` passes from a Mac (with HarfBuzz left out of that check: its bundled C++ sources need a compiler for the Linux target), and it is run in the Ubuntu virtual machine under Xvfb.

| Gap | What the sample does | The upstream statement | The port | Status |
|---|---|---|---|---|
| XE001 | Reloads the HarfBuzz library of SkiaSharp with `RTLD_DEEPBIND` before anything else. | `HarfbuzzWorkaround.cs`, `HarfbuzzWorkaround.Apply()` in `Main` | Not ported: it works around a conflict of the libraries of the .NET runtime (GtkSharp opens GTK with `RTLD_GLOBAL`, and `libHarfBuzzSharp.so`, a shared library of its own, then resolves some of its own symbols from the HarfBuzz of the system and crashes). The port has no such shared library: HarfBuzz is compiled into the executable (`harfbuzz-sys` with its bundled sources), whose references to it are bound when it is linked, so the HarfBuzz that GTK loads cannot take their place. | not applicable |
| XE002 | The socket is a class derived from the socket of GtkSharp, which overrides `OnRealized`, `OnSizeAllocated` and `OnDestroyed`. | `SocketEx.cs` | GtkSharp calls those overrides from the class handlers of the signals `realize`, `size-allocate` and `destroy`; the port makes a plain socket of GTK and connects handlers to the same signals (after the class handler where the override calls the base first, before it for `destroy`). | not a gap of the framework |
| XE003 | GTK through GtkSharp. | the package reference `GtkSharp` | `gtk.rs` opens `libgtk-3.so.0`, `libgdk-3.so.0` and `libgobject-2.0.so.0` at run time through the loader of the base crate and declares the functions the sample calls, as the X11 platform does for its dialogs. `Gtk.Application.Init("myapp", ref args)` is `gtk_init` without the arguments of the command line. | not a gap of the framework |
