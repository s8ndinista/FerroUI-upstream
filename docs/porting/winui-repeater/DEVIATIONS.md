# Repeater deviations and pinned-source corrections

All source comparisons refer to
[WinUI `1af995b98a02d86b1951c4babe35caa269a6d569`](https://github.com/microsoft/microsoft-ui-xaml/tree/1af995b98a02d86b1951c4babe35caa269a6d569/controls/dev/Repeater).
A replacement in this record is a design decision, not an exemption from the
observable behavior it is intended to preserve.

| ID | Source contract | FerroUI decision | Evidence / consequence |
|---|---|---|---|
| WR-01 | C++/WinRT classes, generated factories and dependency-property accessors | Native `FerroObject` class/vtable/property metadata; Rust value types or `Rc` for nonvisual services | [Class and markup design](DESIGN.md#framework-boundaries); every IDL declaration remains in [API.md](API.md) |
| WR-02 | Paired `.h`/`.cpp` and generated partial sources | Consolidate small argument types and layout/context class families in idiomatic Rust modules; split lined-flow policy and row algorithm | The exact many-to-one and one-to-many correspondence is in [SOURCES.md](SOURCES.md) |
| WR-03 | WinRT collection wrappers and `InspectingDataSource` | Extend native `ItemsSource` and `ItemsSourceView` with stable-key mapping rather than introduce a second collection framework | [Source implementation](../../../src/FerroUI.Controls/items_source_view.rs), [source tests](../../../src/FerroUI.Controls/repeater/source_view_tests.rs) |
| WR-04 | Duplicate inclusive selection intervals | Reuse the existing native `IndexRange`, already derived from WinUI | [Range implementation](../../../src/FerroUI.Controls/selection/index_range.rs) |
| WR-05 | `ICustomPropertyProvider` and WinRT reflection | Native typed markup metadata, untyped value conversions and property-change notifications | [Selection metadata](../../../src/FerroUI.Controls/repeater/selection/markup.rs); supports the source's ignored `SelectedItem` custom-property scenario through native metadata |
| WR-06 | `RecyclePool.PoolInstanceProperty` attached to a WinRT `DataTemplate` | Weak template-identity registry because native `IDataTemplate` is a trait object rather than a `FerroObject` | [Pool registry](../../../src/FerroUI.Controls/repeater/recycle_pool.rs); template/pool identity and cleanup require explicit lifecycle tests |
| WR-07 | Windows `QueryPerformanceCounter`, composition rendering callbacks | Native dispatcher time, global animation clock and render-priority fallback | [Scheduler](../../../src/FerroUI.Controls/repeater/build_tree_scheduler.rs); browser-compatible and deterministic under test clocks |
| WR-08 | Windows scrolling surfaces / `ScrollPresenter` integration | Existing FerroUI effective viewport and anchor-provider APIs; compatibility `ItemsRepeaterScrollHost` | [Viewport integration](../../../src/FerroUI.Controls/repeater/viewport_manager.rs); no independent WinUI ScrollPresenter runtime is introduced |
| WR-09 | WinUI ETW, runtime-profiler registration and logging macros | Native logging and typed Repeater/Layout diagnostic hooks | [Dependency map](DEPENDENCIES.md); binary ETW event-schema parity is outside the portable control contract |
| WR-10 | UI Automation through Windows-only SDK interfaces | Native automation peer exposes realized visible descendants in source order; platform adapters remain responsible for native transport | [Peer](../../../src/FerroUI.Controls/repeater/repeater_automation_peer.rs); headless peer tests do not establish an actual assistive-technology session |
| WR-11 | Unattached controls before effective viewport delivery | A finite unbounded realization rectangle is used for direct/offscreen native measure; infinity remains reserved for the fixed-child layout adapter | [Viewport manager](../../../src/FerroUI.Controls/repeater/viewport_manager.rs) |
| WR-12 | Windows composition transition ownership | Native animations restore transient values on completion/cancellation and keep removal elements only until completion | [Animation manager](../../../src/FerroUI.Controls/repeater/animation_manager.rs), [provider](../../../src/FerroUI.Controls/repeater/lined_flow_layout_item_collection_transition_provider.rs) |
| WR-13 | Platform animation preference | Extend existing `IPlatformSettings`; query native Windows UI settings and browser reduced motion where supported; retain enabled default on other backends | Published checkpoint `5acfd247`; native preference and explicit provider opt-out are separate decisions |
| WR-14 | Lined-flow width constraints applied to `DesiredSize` | Translate element limits to FerroUI outer-size coordinates, including margins and native minimum precedence | [Lined-flow implementation](../../../src/FerroUI.Controls/repeater/layouts/lined_flow_layout.rs); metadata constraint ordering remains separately source-defined |
| WR-15 | Aspect-ratio cache resize uses `(last - first) / 2` as its reference index | Correct the reference to `first + (last - first) / 2`, preserving blocks nearest the actual distant viewport | [Pinned `EnsureAndResizeItemAspectRatios`](https://github.com/microsoft/microsoft-ui-xaml/blob/1af995b98a02d86b1951c4babe35caa269a6d569/controls/dev/Repeater/LinedFlowLayout.cpp#L2949); the source expression is relative while the cache indexes source items absolutely |
| WR-16 | Deferred invalidation across detach/reuse | Weak references plus a context generation prevent queued callbacks from the detached host from affecting a new host | [Lined-flow implementation](../../../src/FerroUI.Controls/repeater/layouts/lined_flow_layout.rs); detach also resets anchor/frozen ranges |
| WR-17 | Ignored singleton selection-range event regression | Preserve the pinned runtime's two notifications and explicitly identify the ignored desired-once test as a behavior difference | [Selection test](../../../src/FerroUI.Controls/repeater/selection/tests.rs); this is not reported as an equivalent passing test for the desired-once assertion |
| WR-18 | WinUI TestUI applications and packaged images | Keep every source/asset in the inventory as a reference; provide native FerroUI demonstrations and scenario tests | [Source map](SOURCES.md); exact sample application/page parity is not inferred from control parity |
| WR-19 | Windows UI Automation input and COM activation/finalization tests | Exercise the same portable layout/offset/count/lifetime assertions through native test roots, templates, dispatcher jobs and metadata; preserve native namespace and constructor rules | [Acceptance scenarios](../../../src/FerroUI.Controls/repeater/acceptance_tests.rs), [XAML scenarios](../../../tests/FerroUI.Markup.Xaml.UnitTests/repeater_tests.rs); actual Windows input transport and off-thread COM finalizers are separate platform contracts |

The plain Rust `Result`/programmer-error split follows the existing
[porting guide](../PORTING-GUIDE.md). Native factory and metadata errors retain
typed error information. Invalid layout-context usage, impossible ownership
transitions and forbidden reentrancy are programmer errors. A Rust `panic!`
used for such a precondition is not an implementation placeholder.
