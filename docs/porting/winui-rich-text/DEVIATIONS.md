# Rich text deviations and remaining contracts

This file distinguishes deliberate FerroUI translations from unfinished behavior.
A deliberate architectural translation does not waive missing observable
behavior. File/member status and test evidence live in `mapping.json` and its
generated reports.

## Architectural translations

| ID | WinUI source/contract | Rust/FerroUI translation | Consequence to verify |
|---|---|---|---|
| RT-A01 | C++ dependency objects, COM wrappers, WinRT collections | Existing `Ref<T>` class model, styled/direct properties, shared collection handles, Rust errors and events | Matching property inheritance, observable mutation, object identity, markup access, lifetime and event order. |
| RT-A02 | LineServices plus DirectWrite text analysis and Direct2D rendering | Existing FerroUI formatter, Unicode/shaping/font platform contracts, and `DrawingContext` | Line-break decisions, fallback, glyph clusters, metrics, justification and typography need semantic checks; platform rasterizers can produce different pixels. |
| RT-A03 | `WinUIEdit.dll` and `Microsoft.UI.Text.winmd` | Rust document/editor implementation using the externally documented contract | The native engine source is absent from the requested repository; the public host is not a complete implementation. Every still-unimplemented API stays pending. |
| RT-A04 | Win32 windowless text host, TSF and UI-manager callbacks | FerroUI input-method client, dispatcher, focus, routed input and platform clipboard | Equivalent IME/preedit/caret/surrounding-text behavior must be verified per backend. |
| RT-A05 | Separate C++ headers/implementations and generated WinRT files | Paired sources may share a Rust module; markup/property registration replaces generated ABI plumbing | Every input stays in the map. ABI boilerplate is reference-only; observable members still need individual coverage. |
| RT-A06 | Windows Unicode classification tables | Reuse existing FerroUI Unicode tables and algorithms after version/behavior review | Unicode-version drift, locale-dependent word breaking and dictionary boundaries remain visible rather than assuming table equality. |

## Remaining parity boundaries

| ID | Boundary | Current disposition | Required closure |
|---|---|---|---|
| RT-P01 | Exact LineServices internals and `Ptls-min.h` | External implementation is unavailable in the reference repository. Existing formatting is a reuse candidate, not exact engine parity. | Port visible adapters by semantic role and validate line, hit-test, bidi, justification, trimming and incremental-break behavior. |
| RT-P02 | Full RichEdit text object model | Public XML documentation supplies an exact member inventory; implementation is external. | Implement and test every document/range/selection/format contract or record a reviewed explicit deviation. |
| RT-P03 | RTF features, OLE content, embedded objects, tables, math, advanced formatting | Must be tracked at the content feature and API member level as implementations arrive. | Lossless or explicitly specified behavior with imported/exported fixtures; never report discarded content as a complete rich-text import. |
| RT-P04 | Proofing, prediction, handwriting, candidate windows, touch grippers | Windows adapters are visible; their underlying service implementations are external. | FerroUI service providers and platform tests, including capability absence and cancellation/lifetime behavior. |
| RT-P05 | Accessibility Text/TextRange/annotation patterns | Portable Text/TextRange operations and a native Windows bridge now have explicit partial mappings; Text2, TextEdit, TextChild, annotations, additional attributes and other native backends remain pending. | Close the remaining exact API entries and RT-I10 differences, and verify native Windows clients, screen readers and other backend bridges. |
| RT-P06 | Exact native text appearance | Requires native reference captures with identical fonts, DPI and configuration. | Record comparisons separately from model/unit-test success; do not claim pixel parity from a headless build. |
| RT-P07 | Source/member extraction completeness | Public API identifiers are exact XML entries; internal C++ callable extraction is lexical and cannot resolve macros/conditional compilation. | Review all internal declarations before setting a source file complete. No count of lexical candidates is a parity percentage. |

## Implementation-specific differences

These rows qualify the mapped behavior; they do not mark the remaining native
members complete. Exact targets and test names are linked by [API-MAP.md](API-MAP.md)
and retained for source files in `mapping.json`.

| ID | Pinned source contract and current Rust translation | Observable difference / remaining review |
|---|---|---|
| RT-I01 | Native `TextPointer`, `PlainTextPosition`, document/range positions and `RichTextBlock` selection map to `documents/text_position.rs`, `RichTextDocument`, and rich view/editor range methods. | Public offsets count UTF-16 text, with LF between paragraphs and U+FFFC for embedded controls. Native synthetic element markers are not included. Editing rejects a boundary inside a surrogate pair. Gravity-bearing pointers hold the document weakly. Character-rectangle queries use shaped insertion/caret geometry and affinity; native structural positions and every backward-character rectangle distinction are not implemented implicitly. |
| RT-I02 | Native linked text containers, block layout and `RichTextBlockOverflow` map to one document model, one primary logical view, and weak overflow links. | The primary view owns logical content; columns share content and selection. A second independent primary owner must use a separate model/snapshot. Snapshot copies preserve embedded control identity rather than cloning arbitrary controls, so simultaneous visual ownership remains checked. Native object/container topology and cross-root ownership are not reproduced. |
| RT-I03 | Native text/paragraph formatting and dependency properties map to FerroUI `TextElement`, `Inline`, `Block`, `CharacterFormat` and `ParagraphFormat`. | Rust character and paragraph patches use existing font/brush/decoration collections and layout distances. `LetterSpacing` is a layout distance, whereas native `CharacterSpacing` uses thousandths of an em. Zero paragraph line height requests natural metrics and is projected to the formatter's automatic convention. Native TOM points, format-effect flags, language, tabs, lists and advanced formatting require explicit conversions or separate members. A mapped property accessor does not implement an absent markup alias. |
| RT-I04 | The external RichEdit RTF/clipboard contract maps to `rich_text/rtf.rs` and `rich_text_transfer.rs`. | The bounded RTF1 codec implements its documented subset and returns typed errors for unsupported OLE, pictures, tables/lists, unsupported encodings and unsupported native formatting. In-process transfer preserves the structured snapshot, including controls. External RTF is supplied when encodable alongside plain text; an unencodable snapshot can transfer plain text externally. An advertised malformed or unsupported RTF import errors rather than silently discarding its content. Native stream ABI and every TextGetOptions/TextSetOptions flag remain pending. |
| RT-I05 | Native Hyperlink source activation and navigation map to the shared inline `Hyperlink`, host hit testing, focus tracking, and the existing top-level launcher. | URI/target, tab order, underline style and handled navigation use Rust properties/events. Enter activates on key release, following the source. Native focus-state/XY-focus APIs, access-key UI, sounds, platform-specific navigation behavior and a dedicated hyperlink automation peer require separate implementation. Shared handled arguments and weak host references are tested; they do not supply those omitted services. |
| RT-I06 | `RichEditBox`, `TextBoxBase`, `TextServicesHost` and view/input callbacks map to an editor derived from the rich view, `RichTextEditor`, and the existing input-method/clipboard/dispatcher contracts. | The Rust control uses a surrounding ScrollViewer and framework bring-into-view instead of hosting a native windowless editor. Input prediction and scope describe backend options; they do not supply proofing, prediction or handwriting engines. Native header/description templates, flyouts, selection grippers and UI-manager/candidate services remain pending. |
| RT-I07 | Native editing/clipboard/composition notifications map to Rust model notifications and rich-control routed events. | TextChanging and TextChanged currently follow model mutation notification; native ordering/argument types and cancellable SelectionChanging are not fully reproduced. Clipboard cancellation and revision/selection guards prevent stale asynchronous paste. Composition keeps committed surrounding text separate from preview, and commit/cancel restoration is explicit. Further native event-order and real backend IME tests remain necessary. |
| RT-I08 | External `RichEditTextDocument`, `ITextRange`, `RichEditTextRange` and `ITextSelection` map to Rust facades over the same document/editor. | The facade exposes grapheme, word, sentence, paragraph and document units, live gravity ranges, typed errors, composite Uniform/Mixed formatting results, rich replacement, geometry and grouped undo. Case-insensitive search uses Unicode lowercase mappings rather than locale collation or full case folding. Native option flags, layout/table units, arbitrary stories, streams, image/math objects, default-format APIs and platform TOM ABI remain individually pending. UI Automation has a separate unit/attribute contract and is tracked separately. |
| RT-I09 | Native TextHighlighter/TextRange/highlight-region collections and TextHighlightMerge map to `TextHighlighter`, `TextHighlightRange`, shared collections and a half-open region merge. | TextHighlighterBase is a projection-only base and maps to FerroObject rather than a redundant public class. The Rust value name TextHighlightRange avoids the existing live document TextRange; XAML retains TextRange with signed StartIndex/Length. Collection insertion copies values, while markup temporarily boxes mutable fields. Invalid/empty ranges do not paint. Later layers replace both brushes using the layer's own defaults. Scalar normalization for visual spans does not rewrite the public range value. Native high-contrast/raster and all inline-object rendering cases remain separate conformance work. |
| RT-I10 | `CUIATextProviderWrapper`/`CUIATextRangeProviderWrapper`, native text attribute IDs and the exact XAML provider APIs map to portable `ITextProvider`/`ITextRangeProvider`, shared rich provider services, and Windows `AutomationNode`/`TextRangeNode`. | The six Text and eighteen TextRange operations use live weak ranges, typed errors, single contiguous selection, embedded controls, clipped shaped geometry and sixteen formatting/state attributes. The Windows boundary marshals COM identities, arrays, BSTRs, HRESULTs, reserved Mixed/NotSupported values, and root/screen coordinates through the existing dispatcher/ABI. Line promotes to Paragraph without a complete laid-out document, and Page promotes to Document without a complete overflow chain. The rich TOM facade's five units are distinct from these seven UIA units. Dedicated hyperlink peers, Text2/caret/annotation, TextEdit/TextChild, additional attribute families, non-Windows native text bridges and real Windows client/screen-reader runs remain pending. Presence of native bridge tests or a cross-compile does not assert native execution. |
