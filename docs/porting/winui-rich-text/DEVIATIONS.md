# Rich text deviations and remaining contracts

This file distinguishes deliberate FerroUI translations from unfinished behavior.
A deliberate architectural translation does not waive missing observable
behavior. File/member status and test evidence live in `mapping.json` and its
generated reports.

## Architectural translations

| ID | WinUI source/contract | Rust/FerroUI translation | Consequence to verify |
|---|---|---|---|
| RT-A01 | C++ dependency objects, COM wrappers, WinRT collections | Existing `Ref<T>` class model, styled/direct properties, shared collection handles, Rust errors and events | Matching property inheritance, observable mutation, object identity, markup access, lifetime and event order. |
| RT-A02 | LineServices plus DirectWrite text analysis and Direct2D rendering | Existing FerroUI formatter, Unicode/shaping/font platform contracts, and `DrawingContext` | Line-break decisions, fallback, glyph clusters, metrics, justification and typography need semantic checks; platform rasterizers can produce different pixels. |
| RT-A03 | `WinUIEdit.dll` and `Microsoft.UI.Text.winmd` | Rust document/editor implementation using the externally documented contract | The native engine source is absent from the requested repository; the public host is not a complete implementation. Every still-unimplemented API stays pending. |
| RT-A04 | Win32 windowless text host, TSF and UI-manager callbacks | FerroUI input-method client, dispatcher, focus, routed input and platform clipboard | Equivalent IME/preedit/caret/surrounding-text behavior must be verified per backend. |
| RT-A05 | Separate C++ headers/implementations and generated WinRT files | Paired sources may share a Rust module; markup/property registration replaces generated ABI plumbing | Every input stays in the map. ABI boilerplate is reference-only; observable members still need individual coverage. |
| RT-A06 | Windows Unicode classification tables | Reuse existing FerroUI Unicode tables and algorithms after version/behavior review | Unicode-version drift, locale-dependent word breaking and dictionary boundaries remain visible rather than assuming table equality. |

## Remaining parity boundaries

| ID | Boundary | Current disposition | Required closure |
|---|---|---|---|
| RT-P01 | Exact LineServices internals and `Ptls-min.h` | External implementation is unavailable in the reference repository. Existing formatting is a reuse candidate, not exact engine parity. | Port visible adapters by semantic role and validate line, hit-test, bidi, justification, trimming and incremental-break behavior. |
| RT-P02 | Full RichEdit text object model | Public XML documentation supplies an exact member inventory; implementation is external. | Implement and test every document/range/selection/format contract or record a reviewed explicit deviation. |
| RT-P03 | RTF features, OLE content, embedded objects, tables, math, advanced formatting | Must be tracked at the content feature and API member level as implementations arrive. | Lossless or explicitly specified behavior with imported/exported fixtures; never report discarded content as a complete rich-text import. |
| RT-P04 | Proofing, prediction, handwriting, candidate windows, touch grippers | Windows adapters are visible; their underlying service implementations are external. | FerroUI service providers and platform tests, including capability absence and cancellation/lifetime behavior. |
| RT-P05 | Accessibility Text/TextRange/annotation patterns | Portable Text/TextRange/Text2/TextChild operations, hyperlink peers and a native Windows bridge have explicit partial mappings. TextEdit composition ranges and cause-aware events now have portable and Windows bridge implementations. Conversion-target backend data, the public peer event path, annotation lookup, remaining attributes and other native backends remain pending. | Close the remaining exact API entries and RT-I10 differences, and verify native Windows clients, screen readers and other backend bridges. |
| RT-P06 | Exact native text appearance | Requires native reference captures with identical fonts, DPI and configuration. | Record comparisons separately from model/unit-test success; do not claim pixel parity from a headless build. |
| RT-P07 | Source/member extraction completeness | Public API identifiers are exact XML entries; internal C++ callable extraction is lexical and cannot resolve macros/conditional compilation. | Review all internal declarations before setting a source file complete. No count of lexical candidates is a parity percentage. |

## Implementation-specific differences

These rows qualify the mapped behavior; they do not mark the remaining native
members complete. Exact targets and test names are linked by [API-MAP.md](API-MAP.md)
and retained for source files in `mapping.json`.

| ID | Pinned source contract and current Rust translation | Observable difference / remaining review |
|---|---|---|
| RT-I01 | Native `TextPointer`, `PlainTextPosition`, document/range positions and `RichTextBlock` selection map to `documents/text_position.rs`, `RichTextDocument`, and rich view/editor range methods. | Public offsets count UTF-16 text, with LF between paragraphs and U+FFFC for embedded controls. Native synthetic element markers are not included. Editing rejects a boundary inside a surrogate pair. Gravity-bearing pointers hold the document weakly. Character-rectangle queries use shaped insertion/caret geometry and affinity; native structural positions and every backward-character rectangle distinction are not implemented implicitly. |
| RT-I02 | Native linked text containers, block layout and `RichTextBlockOverflow` map to one document model, one primary logical view, and weak overflow links. | The primary view owns logical content; columns share content and selection. A second independent primary owner must use a separate model/snapshot. Snapshot copies preserve embedded control identity rather than cloning arbitrary controls, so simultaneous visual ownership remains checked. Native object/container topology and cross-root ownership are not reproduced. |
| RT-I03 | Native text/paragraph formatting and dependency properties map to FerroUI `TextElement`, `Inline`, `Block`, `CharacterFormat` and `ParagraphFormat`. | Rust character and paragraph patches use existing font/brush/decoration collections and layout distances. `LetterSpacing` is a layout distance, whereas native `CharacterSpacing` uses thousandths of an em. Zero paragraph line height requests natural metrics and is projected to the formatter's automatic convention. TOM line spacing and indentation helpers explicitly convert points to layout units. Signed indents are separate from nonnegative margins; Single, OneAndHalf, Double, AtLeast, Exactly and Multiple drive layout, while Percent is rejected as in the native RichEditBox contract. Inherited language is implemented with the resolution and RTF limits in RT-I11; remaining format-effect flags, tabs, lists and advanced formatting need separate implementations. A mapped property accessor does not implement an absent markup alias. |
| RT-I04 | The external RichEdit RTF/clipboard contract maps to `rich_text/rtf.rs` and `rich_text_transfer.rs`. | The bounded RTF1 codec implements its documented subset and returns typed errors for unsupported OLE, pictures, tables/lists, unsupported encodings and unsupported native formatting. In-process transfer preserves the structured snapshot, including controls. External RTF is supplied when encodable alongside plain text; an unencodable snapshot can transfer plain text externally. An advertised malformed or unsupported RTF import errors rather than silently discarding its content. The typed get/set flag surface implements the separately mapped modes; object-text, numbering, hidden-text modes, UnicodeBidi insertion mode and ApplyRtfDocumentDefaults fail explicitly. Rust Read/Write stream operations are implemented with the explicit policy in RT-I12; native stream ABI and unsupported content remain pending. RTF sl/slmult retains multiple spacing; fi/li/ri preserves signed indents. External RTF normalizes horizontal FerroUI margins into indentation because RTF has no equivalent paragraph-outside-margin field. |
| RT-I05 | Native Hyperlink source activation and navigation map to the shared inline `Hyperlink`, host hit testing, focus tracking, and the existing top-level launcher. | URI/target, tab order, underline style and handled navigation use Rust properties/events. Enter activates on key release, following the source. A dedicated weak hyperlink automation peer now supplies name precedence, Invoke, focus and TextChild ranges. Native focus-state/XY-focus APIs, access-key UI, sounds, platform-specific navigation, the first-rectangle clickable-point specialization and complete automation property events require further implementation. Shared handled arguments and weak host references are tested; they do not supply those omitted services. |
| RT-I06 | `RichEditBox`, `TextBoxBase`, `TextServicesHost` and view/input callbacks map to `RichEditBox : TemplatedControl`, one persistent `RichEditBoxTextPresenter : RichTextBlock`, `RichTextEditor`, and existing input-method/clipboard/dispatcher contracts. | The control keeps one model/history across template replacement. ContentElement accepts framework content hosts; the presenter owns document-only logical scrolling and owner-relative IME geometry. Header, HeaderTemplate, Description and placeholder use actual template parts. The control owns focus, routed events and automation; its presenter is raw and has no independent Text pattern. Owned context-flyout focus retains selection/composition state through actual popup identity. Native IME transport retention across popup roots, touch grippers, candidate/UI-manager services and real backend behavior remain separate work. Theme mapping has its own pinned inventory and deviations. |
| RT-I07 | Native editing/clipboard/composition notifications map to Rust model notifications and rich-control routed events. | TextChanging runs synchronously after backing-model mutation, with IsContentChanging; TextChanged is dispatched at LOADED with RoutedEventArgs and a weak generation-checked owner. SelectionChanging exposes a cancellable proposal to both view and TOM; reentrant requests override cancellation and publish the accepted selection once. Clipboard cancellation and revision/selection guards prevent stale asynchronous paste. Composition keeps committed surrounding text separate from preview, and commit/cancel restoration is explicit. Further native event-order and real backend IME tests remain necessary. |
| RT-I08 | External `RichEditTextDocument`, `ITextRange`, `RichEditTextRange` and `ITextSelection` map to Rust facades over one document/editor. | Native-valued Character, Word, Sentence, Paragraph, Line, Story and HardParagraph units are implemented. Character advances Unicode scalars without splitting surrogate pairs; native Cluster remains pending and is not aliased to grapheme navigation. Word includes following ASCII blanks, Sentence follows the documented native punctuation rules, and HardParagraph distinguishes structural paragraphs from inline soft breaks. Line uses a weak associated complete untrimmed layout, falls back to Paragraph when headless, and reports unavailable/incomplete geometry explicitly. StartOf/EndOf, one-based and end-relative indices, collapse counts and signed movement have focused tests. Public offsets exclude the synthetic terminal CR; arbitrary stories, remaining units, advanced content and the native TOM ABI remain pending. Search uses Unicode lowercase mappings rather than locale collation or full case folding. Streams use RT-I12. |
| RT-I09 | Native TextHighlighter/TextRange/highlight-region collections and TextHighlightMerge map to `TextHighlighter`, `TextHighlightRange`, shared collections and a half-open region merge. | TextHighlighterBase is a projection-only base and maps to FerroObject rather than a redundant public class. The Rust value name TextHighlightRange avoids the existing live document TextRange; XAML retains TextRange with signed StartIndex/Length. Collection insertion copies values, while markup temporarily boxes mutable fields. Invalid/empty ranges do not paint. Later layers replace both brushes using the layer's own defaults. Scalar normalization for visual spans does not rewrite the public range value. Native high-contrast/raster and all inline-object rendering cases remain separate conformance work. |
| RT-I10 | `CUIATextProviderWrapper`/`CUIATextRangeProviderWrapper`, text attributes and XAML provider APIs map to portable Text/TextRange/Text2/TextChild/TextEdit services and Windows AutomationNode/TextRangeNode. | The six Text and eighteen TextRange operations use weak live UTF-16 ranges, single selection, embedded controls, clipped shaped geometry and 25 supported attributes. The semantic owner is separate from its raw presenter. ScrollIntoView aligns the first or last selected line within the existing viewport and includes linked overflow geometry. Text2 caret and TextChild canonical hyperlink identity are implemented. TextEdit active-composition ranges and accepted delta/finalization payloads share editor state; a conversion target is absent until the backend supplies one. TextEdit inherits Text as a sibling of Text2. The Windows boundary handles COM identity, BSTR/SAFEARRAY/HRESULT values, dispatcher access and root/screen transforms. Line/Page fallback rules are distinct from TOM units. Public AutomationPeer.RaiseTextEditTextChangedEvent, annotation lookup, further attributes and other native backends remain pending. Linux-hosted Win32 tests do not assert native Windows clients, screen readers or actual OS execution. |
| RT-I11 | Native TextElement.Language, ITextCharacterFormat.LanguageTag, ValidateXmlLanguage and text formatting language services map to inherited CultureInfo values, CharacterFormat language patches and existing FerroUI font fallback/shaping. | Empty language resolves through IPlatformSettings preferred application language with the native en-US fallback; nonempty validated tags stay intact. Validation follows the pinned XML-language grammar, which is broader than registered BCP-47 tags. Windows ResolveLocaleName, the ordered MUI fallback-language list and all locale IDs are not reproduced by the finite framework culture table. Supported RTF deflang/lang values and plain resets round-trip; unrepresentable tags and unknown RTF locale IDs fail explicitly. Far-East/dual proofing language and system linguistic services remain pending. |
| RT-I12 | Native document/range LoadFromStream, SaveToStream, GetTextViaStream and SetTextViaStream map to Rust Read/Write with TextStreamOptions. | Plain text explicitly selects UTF-8, UTF-16LE or UTF-16BE. Matching BOMs are removed on input; contradictory BOMs and malformed scalars fail. Optional output BOMs count toward the default 16 MiB bound. RTF uses raw codec bytes and only the default UTF-8/no-BOM policy, without transcoding. Flags/policy are checked before I/O, complete input is parsed before mutation, and output is encoded before the first write. Readers/writers retain current position and caller ownership; methods never seek, truncate, flush or close. I/O output failure may leave a written prefix. This is a deliberate framework stream translation, not a claim of undocumented native engine encoding defaults. |
| RT-I13 | Native TextEdit composition notifications map to RichTextCompositionChange and disposable cause-aware provider observations. | Preview payloads contain only accepted replacement text after normalization/filtering/limits; cursor-only movement emits no text cause. A successful commit emits one complete accepted finalization and one undo unit. Explicit cancellation emits one empty finalization. Failed or read-only operations do not invent success/cancellation events. Group rollback discards queued causes and preview-only groups never add history. Internal model mutation identity invalidates stale previews before public batched notifications; an independently held model batch can delay public Changed beyond the cause callback. AutoCorrect and conversion-target causes are not inferred from ordinary edits. Native TextCompositionEventArgs range fields and full backend event ordering remain pending. |
| RT-I14 | Native inherited text presentation and format dirtiness use FerroUI property provenance and `IInlineHost::invalidate_layout`. | Ancestor presentation, parent attachment and mutable inherited feature/decoration changes rebuild the view without incrementing the document revision or invalidating undo/composition. A local formatting edit, including clearing a local value to expose inheritance, still changes the model. The property event carries origin separately from resulting binding priority; owned event arguments retain it. Snapshots preserve assigned base values and continue to inherit the current theme after undo. This is an explicit framework translation with focused regression evidence; it does not reproduce all native property-engine dirty flags or claim native pixel equivalence. |
